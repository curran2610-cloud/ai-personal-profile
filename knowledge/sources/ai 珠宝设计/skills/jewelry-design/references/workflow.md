# 项目工作流

## 目录与版本
```
projects/<project-id>/
  brief.json
  references/                    原始参考与来源
  versions/v001/
    manifest.json                父版本、变更理由、状态
    input-inventory.json          来源哈希和阅读状态
    spec.json                     确认项、假设、待定项
    model.blend
    model.stl                     仅在需要交换/打样时输出
    scene-snapshot.json           模型哈希、几何方向、实际相机
    orientation-review.json
    validation.json
    change-log.md
    views/                        仅白模
```
上述文件按真实阶段产生；未建模时不生成伪模型、空 STL 或伪通过报告。
`new-version` 只创建 manifest。完成后在 manifest 的 artifacts 字段登记实际文件 SHA256。状态 draft → review → approved；批准应有批准者与依据。已交付/批准目录不再写入，任何修复用新版本。试验中间文件放当前 draft 的 work/，不要混作交付。

## 需求与来源
扫描当前项目所有需求、规格及引用资料；对每项记录 path、sha256、role、read_status。哈希仅说明文件身份，不代表已经读过。没有文本提取能力的文件必须说明未读取。
历史 studies 作为知识教训；需要引用旧图时明确复制或建立路径引用并注明用途。不自动把所有历史资产纳入新设计。
每个数值记录 value、unit、status（confirmed/source/assumed/measured/unknown）、source、tolerance（未知可空）。如先设内径，应写本项目假设，不写“常规标准保证正确”。

## 审美积累（任务需要时）
用户只提供方向时，主动检索真实案例并注明来源，解释可提取的比例/线条/留白关系，记录用户偏好。白模执行任务已有足够方向时直接推进，不每轮重做审美研究。

## 坐标、朝向与相机
首版选定主体框架 `JEWELRY_FRAME`，记录指轴、正面、佩戴向上。框架可随整个首饰移动；不要每轮重新解释坐标。
相机在模型外部，单独记录 camera name、matrix_world、type、ortho_scale、resolution、clip、单位。三台视图的观察轴互相垂直。斜视仅辅助，不冒充第三个正交视图。
模型绕世界坐标旋转时，方向证据通过主体框架换算；相机变化不会改变元素身份和局部朝向。

## 工程检查按阶段分层
| 阶段 | 可交付 | 必须说明 |
|---|---|---|
| 概念白模 | 可编辑模型、白模多视图、尺寸假设 | 不承诺制造；检查元素数量、方向与主要连接关系 |
| 几何校验 | 封闭性、退化面、分量、单位回读报告 | 仍不能替代薄壁、结构和工艺判断 |
| 打印候选 | 交换文件、已知薄边、建议检查区域 | 指定设备的支撑/切片/试印尚未完成时明确标注 |
| 生产审核 | 工厂约束、真实石型、石座、余量与审核记录 | 由明确工艺条件支持，不能自动从网格检查升级 |

没有完整工艺参数时继续粗模，不因未知缩水率阻塞概念探索。真正不可解的设计冲突才请求用户决策。
零非流形边不等于无自相交；一个连通分量不等于连接牢靠；射线抽检最小值不等于全局最小壁厚；定位孔不等于石座；预览石不等于已固定。
任何已知失败项在对外摘要中披露。工艺修复改变可见装饰、符号辨识、留空或比例时，记录设计影响再评审。

## 重现与交接
记录 Blender 版本、构建脚本、参数、随机种子（若用到）、输入哈希和输出哈希。最终清理后重新保存、回读并验证，不引用清理前统计。
一名建模 Agent 独占写入该版本。审查 Agent 仅报告缺陷；统筹整合变更。任务暂停时写明最后成功步骤及待做项，不假报完成。
