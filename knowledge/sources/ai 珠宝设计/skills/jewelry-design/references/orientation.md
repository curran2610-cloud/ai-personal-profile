# 装饰方向锁定协议

## 通用含义
每个有方向的元素保持自己已确认的方向，不是让鸢尾花、荆棘或所有装饰都朝一个世界轴。不同实例可以合法地左右相对、环绕、朝外；各实例分别登记。
本协议锁方向及手性，不锁位置和尺寸；位置/比例如需保持，应另列尺寸与坐标检查。

## Blender 准备
- 主体放在 `JEWELRY_FRAME` 框架下（建议 Empty 父级），整个首饰刚性移动时框架一起移动。装饰可更深层级，导出器会计算相对框架变换。
- 需要检查的每个 MESH 对象设置自定义字符串属性 `jewelry_element_id`（唯一、跨版本稳定）。
- 在该对象建立四个**非空顶点组**：`anchor_origin`、`anchor_forward`、`anchor_up`、`anchor_right`。用它们的几何质心表示语义原点/尖端/上方/右侧。顶点组标签不是装饰名字；可适用于动物、花、文字、徽记等。
- 四个组必须形成非退化三维有向基。平面对称纹样无法形成足够语义证据时，报告未验证，改用实体厚度中的正面/背面语义点或人工标记复核，不能伪造锚点。
- `origin→forward` 和 `origin→up` 用于检测旋转；三轴叉积符号用于检测几何镜像；相对变换行列式另外检查未应用的负缩放。
- 顶点组应绑定实际几何，禁止仅放四个独立 Empty 并声称它们能发现网格内部倒置。

## 导出
先保存对应版本的 .blend，再在 Blender 后台执行：
```
Blender --background /absolute/project/versions/v001/model.blend --python /absolute/skill/scripts/export_scene.py -- --project-id PROJECT_ID --out /absolute/project/versions/v001/scene-snapshot.json
```
导出器从最终 evaluated mesh 读取顶点组对应坐标；同时校验原始与求值拓扑是否一致。拓扑改变的修改器/重拓扑视为锚点映射未验证，不猜测索引意义。
如果有多个同名 ID、缺少框架、没有方向对象、锚点组为空、坐标退化，报告失败或未验证，绝不默认通过。
第一次快照仅建立**候选基线**，由用户确认/明确的任务依据记录在版本审核中；不是与自己比较就证明方向正确。
修改后：
```
python3 scripts/workflow.py compare BASELINE.json CURRENT.json --out NEW_REPORT.json
```
报告退出码：0=所登记方向通过；2=存在失败或未验证；1=输入/调用错误。
默认角度容差 1° 是项目工具初始值，不是珠宝行业标准，可通过 `--tolerance-deg` 明确设置并进入报告。

## 防止误判与漏判
- 换相机：不参与方向比较，另行记录相机。
- 主体与框架整体转动：相对方向不变。
- 主体框架整体负缩放镜像：另外比较框架世界手性，标记失败；整体刚性旋转仍通过。
- 只翻转某元素：几何方向/变换手性异常。
- 把镜像应用到网格：即使变换回到单位矩阵，实际几何锚点仍反向。
- 拓扑或组成员变化：标记未验证，重新绑定锚点并复核。不能自动把更新后的文件覆盖批准基线。
- 新增/丢失 ID：新增标记未验证，丢失标记失败；必须解释变化。
- 只翻转未被选入锚点的局部花瓣可能不被本工具捕获。因此关键子部件需要单独 ID/方向证据，且保留多视图人工形态检查；工具不承诺检测所有几何变化。
- 合法镜像双件：先在初始基线中按不同 ID 建立各自预期；后续只检测它们各自是否发生未授权变化。
- compare 的 pass 只表示两份证据相对一致；报告始终注明 baseline_approval_checked=false。批准状态必须另查版本 manifest，工具不得把首版自比当成批准。
